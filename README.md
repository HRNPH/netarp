# NetArp

Network device discovery using ARP scanning. SQLite storage (SeaORM), optional
GraphQL API, optional InfluxDB export, optional hostname aliasing.

## How it works

NetArp sends ARP requests across your subnets, collects replies, and maintains
a device inventory in SQLite:

- **device** — current state per MAC: IP, alias, vendor, first/last seen
- **event** — history: `discovered`, `ip_changed`, `alias_set`
- **scan** / **scan_result** — every scan run and its per-device outcomes

Every scan cycle it can also:

- resolve a list of hostnames (from a file, e.g. generated from another
  system) and attach them as device aliases
- export the current device list to InfluxDB (line protocol) for Grafana

## Feature flags

| Feature    | Default | What it enables                                   |
|------------|---------|---------------------------------------------------|
| `graphql`  | ✅      | GraphQL API + playground on `[api].bind`           |
| `influx`   | ✅      | InfluxDB export (`[influx]` config section)        |

Build without either: `cargo build --no-default-features`.

## Configuration

Layered — later wins: **defaults < TOML file < `NETARP_*` env < CLI flags**.

Config file search order: `--config path`, `./netarp.toml`, `/etc/netarp/config.toml`.
See [`netarp.toml.example`](netarp.toml.example).

```toml
[scanner]
subnets = ["192.168.1.0/24", "192.168.2.0/24"]   # omit = autodetect
interval_secs = 120
timeout_secs = 5
# once = true                                    # scan once, exit (testing)

[database]
url = "sqlite:///var/lib/netarp/netarp.db?mode=rwc"

[api]          # feature "graphql"
bind = "0.0.0.0:4000"

[influx]       # feature "influx"; presence enables export
url = "http://192.168.3.100:8086"
org = "magika"
bucket = "network"
measurement = "lan"

[names]        # presence enables hostname aliasing
file = "/etc/netarp/names.txt"
suffix = "magika"
```

Environment (highest before CLI): `NETARP_INTERFACE`, `NETARP_INTERVAL_SECS`,
`NETARP_TIMEOUT_SECS`, `NETARP_ONCE`, `NETARP_DB_URL`, `NETARP_API_BIND`,
`NETARP_INFLUX_URL`, `NETARP_INFLUX_ORG`, `NETARP_INFLUX_BUCKET`,
`NETARP_INFLUX_TOKEN`, `NETARP_NAMES_FILE`, `NETARP_NAMES_SUFFIX`.

The `[names]` file is one hostname per line (re-read every scan), so it can be
regenerated by cron/timers from whatever knows your device names. Bare names
get `suffix` appended; names containing dots are used as-is.

## Run

Requires root/CAP_NET_RAW for raw ARP sockets.

```bash
sudo RUST_LOG=info ./netarp --config /etc/netarp/config.toml
```

Single test scan:

```bash
sudo ./netarp --once -s 192.168.1.0/24 -s 192.168.2.0/24
```

### Docker

Images are published to `ghcr.io/hrnph/netarp` (multi-arch amd64/arm64,
distroless). ARP needs host networking and NET_RAW:

```yaml
services:
  netarp:
    image: ghcr.io/hrnph/netarp:v0.2.0
    restart: unless-stopped
    network_mode: host
    cap_add: [NET_RAW]
    environment:
      NETARP_INFLUX_TOKEN: "${NETARP_INFLUX_TOKEN}"
    volumes:
      - netarp-data:/var/lib/netarp
      - ./netarp.toml:/etc/netarp/config.toml:ro
      - ./names.txt:/etc/netarp/names.txt:ro

volumes:
  netarp-data:
```

## GraphQL

With feature `graphql`, query at `http://host:4000/graphql`:

```graphql
{ allDevices { ip mac alias firstSeen lastSeen } }
{ latestDevices(withinMinutes: 10) { ip mac alias } }
{ deviceHistory(mac: "de:a6:32:..:..:..") { kind detail timestamp } }
{ scans(limit: 5) { id startedAt status deviceCount } }
```
